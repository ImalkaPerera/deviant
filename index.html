The problem

47 routes check who is calling. The 48th exports every user's data.

Every codebase runs on unwritten rules: every route checks auth, every CI job has a timeout, every action is pinned to a commit. Nobody writes them down, so nobody checks them.

Code review catches what the reviewer remembers. AI coding agents write code that looks right and passes tests, but can quietly forget the check every other route has.

Deviant counts what your code already does and points at the rare item that breaks the pattern, with the history behind it.

How it works

Count first. Judge second. Then read the code.

The scan is plain math on your machine: no AI, no API key, the same answer every time. The Claude Code skill adds the judgement.

01

Group

A check lists similar things: every FastAPI route, every CI job, every workflow step.

02

Count

Plain statistics find the pattern ("47 of 48 do this") and the rare items that break it.

03

Show the evidence

Each exception comes with its git history: who changed it, in which commit, and whether they wrote the compliant ones.

04

Judge Skill

Claude labels each exception bug, intentional or unsure, and cites the line, test or commit that shows it.

05

Review Skill

Then it compares every handler and job with its siblings, for the bugs no count can see.

✓

Safe on untrusted code

It only reads and parses files, and git evidence uses read-only commands. Scanned code is data, never instructions.

How it is different

It finds what only counting can see.

Deviant does not replace your linter or your reviewers. It catches the exception to a rule nobody wrote down, and with the skill it gives an AI reviewer a method instead of a blank page.

What it checks

FastAPI routes and GitHub Actions, today.

Each check compares an item with its peers. A new check is one Python file.

FastAPI routes

A route missing the auth or rate limit its neighbours have. Auth set on a router or parent app counts, so routes protected from above are not reported.

GitHub Actions

An action not pinned to a commit, a job with no timeout or concurrency setting, a workflow with no permissions block, a step that ignores its own failure.

Get started

Two commands. Or one.

You need Python 3.10 or newer and git.

The scan

# install, then scan with git history
pip install deviant-scan
deviant-scan path/to/project --with-git
# or run it once, without installing
uvx deviant-scan path/to/project --with-git

Add --json for tools and --fail-on-findings to fail a CI job.

In Claude Code Skill

# install the plugin once
/plugin install deviant --marketplace ImalkaPerera/deviant
# judge each exception and review the code
/deviant:deviant path/to/project

Each finding comes back as bug, intentional or unsure, with proof. How the skill works.

FAQ

Questions people ask first.

Does my code leave my machine?

Not with the scan. It runs locally, makes no network calls and never runs your code. The Claude Code skill works like any Claude Code session: Claude reads the files it judges.

Which languages and frameworks does it check?

FastAPI routes in Python, and GitHub Actions workflows. Each check is one Python file, so new ones (Flask, Express, Dockerfiles and more) are welcome contributions.

What does it cost?

The scan is free and open source. The skill uses your Claude plan. In the benchmark a run cost about 10 cents in API terms, a third less than asking Claude alone.

My project is small and the scan shows nothing. Why?

One exception is only strong evidence in a group of about 20 or more similar items, so small projects often show nothing on purpose. --inventory lists the weaker leads, and the skill reviews the code itself.

What if a route is public on purpose?

The skill labels it intentional when the code, a test or a comment says why. A comment such as "public endpoint" above the route also silences it, and .deviant/config.json can name auth helpers with unusual names.
